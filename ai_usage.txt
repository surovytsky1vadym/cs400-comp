Student
- Architecture and decisions:
  - program order: structs first, then functions, then statements; a function
    after a statement is a compile error (tests/err/fn_after_statement);
  - function parameters are immutable; assigning to one is a compile error
    (tests/err/fn_param_not_mut);
  - structs are passed and returned by value: parameters are copied into
    entry-block slots, struct values are built with insertvalue.
- Verification: checked the .expected outputs of the Practice 6 tests by hand
  (exit codes of the valid programs, error messages and line:column positions
  of the error programs) before accepting them.
- Review and acceptance: ran the full suite (tests/ok, tests/err), checked the
  generated IR and AST dumps, committed the result.

AI
- grammar.ebnf, Lexer: struct, fn, ",", "(", ")", ".", "->".
- Parser: struct and fn definitions (top level only, before statements), field
  chains (a.b.c), calls with argument lists, nested {} initialisers.
- SemanticChecker:
  - struct table: unknown fields, wrong initialiser count, {} used for builtin types;
  - function table: argument count, argument/parameter types, exit type,
    parameters immutable, no top-level variables inside functions;
  - mutability along field chains (const object / const link).
- Tests: 11 error tests in tests/err (fn_*, struct_*), 8 valid tests in tests/ok
  (recursive fib, nested calls, i64 params, struct params/results, field writes,
  nested chains and initialisers) with .expected and .ast files.
